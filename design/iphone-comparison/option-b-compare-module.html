Option B — design notes

The brief

Fix the table without renegotiating the page. Everything above and below the comparison module is untouched — same copy, same IA, same templates — so this ships as one component, not a redesign programme.

What was wrong with the table

  • 14 × 7 = 98 cells. It asks the visitor to do the comparison work. On mobile it becomes a horizontal-scroll block where you lose the model name the moment you scroll to Battery.
  • Prose in every cell. "A19 Chip with 5 core GPU and 6 core CPU with 16-core Neural Engine" is a spec sheet, not an answer. There is no way to tell at a glance which chip is better.
  • No prices. A comparison page on a retailer site with no commercial information — the visitor has to leave to find out what anything costs.
  • No pictures. The editorial section has the storytelling, the table has the facts, and neither has an image of the phone.
  • No CTAs. You can read all 98 cells and still have nowhere to click.
  • Doesn't scale. Each launch adds rows to a table that is already too long.

What the module does instead

  • Two or three, not fourteen. Selection first, comparison second — the real mental model.
  • Presets do the work. "Latest three", "Pro vs Pro Max", "Best value" cover most intents in one tap.
  • Answer first, spec second. Each cell leads with a short verdict and keeps the full spec string underneath.
  • Differences only. One toggle collapses everything the models share, so the page answers "what am I paying extra for?".
  • Best-in-row highlighting. Battery, cameras and chip generation are ranked automatically.
  • Price and CTA in the sticky header. Commercial information travels with the comparison.
  • Phones drawn to relative screen size — the single most common real-world decision factor, and currently buried in a text string.

Launch readiness

A new model is a data entry, not a layout change. Add the object, tag it new, and it appears at the front of the rail, in the "Latest" preset and in the full table. A pre-announcement model can carry a "Coming soon / Register interest" state with empty spec values.

Effort & risk

Roughly one sprint for one front-end dev plus a content pass to write the plain-English verdict lines. No CMS re-platforming, no new page template, no nav changes. The full table stays in place underneath, so the SEO content and the accessibility fallback are unchanged.

Content issues found in the live table

Worth fixing whichever option you pick:
  • iPhone 16 Plus is listed as a 6.1-inch display. It is 6.7-inch — and it is the only reason to buy it over the 16.
  • iPhone 15 and 15 Plus are credited with a "12MP Telephoto with 2X Optical Zoom". Neither has a telephoto lens; the 2x is a crop of the 48MP main sensor.
  • iPhone 15 Pro is listed with an "A17 Bionic Chip" while the 15 Pro Max says "A17 Pro". Both are A17 Pro.
  • iPhone 16 Pro Max lists "48MP Macro" as a fourth camera. Macro is a mode on the ultra-wide, not a separate lens.
  • iPhone 17 Pro's camera cell repeats "48MP Fusion camera system" twice.
  • Row order (17, Air, 17 Pro, 17 Pro Max, 17e, 16e, 16, 16 Plus…) matches neither price nor tier nor the order of the editorial section above it.

Not in this option

Guided "help me choose", filtering, trade-in values, upgrade personalisation and the launch hero are all Option A. Option B is deliberately the smallest change that fixes the actual complaint.
